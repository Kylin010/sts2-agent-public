# 杀掉一只帝皇蟹后，不应计算对死亡目标转身的背击惩罚

结论：`SurroundedPower.AfterDeath` 会自动面向唯一存活的蟹。当前组合评分 `_facing_extra` 没有接收组合完成后的存活列表，仍按最后一张单体牌的目标计算方向；杀死Crusher的组合可能被额外扣除并不会发生的Rocket背击伤害。默认关闭候选 `crab_facing_after_kill` 只在标准双蟹、公开Surrounded徽章、无已知复活机制、预计至少一只死亡时停止这项额外朝向惩罚。

## 源码

`SurroundedPower.cs:90` 的 AfterDeath 在死亡未被阻止时，检查剩余可攻击敌人；全部具有同侧BackAttack标记时，自动UpdateDirection至存活者。`:77` BeforeCardPlayed确实会先转向目标，但该朝向随后会被死亡触发更新，不能作为敌方回合最终朝向。`:46` 背击倍率为1.5。

`combat._score` 已经有alive_after用于死亡与蟹之怒，但调用_facing_extra没有使用它。新候选把该列表传入。蟹之怒加力量/99格挡的旧扣分继续存在；本改动只删除朝向造成的虚构额外伤害，没有承诺解决蟹之怒顺序或所有格挡。

## 可复现的纯局面

公开假设：Crusher10血、Rocket200血，本回合Rocket激光显示38，玩家面向Rocket。打一张预览20伤害的攻击杀Crusher。旧朝向公式使用最后目标Crusher，算出Rocket57，即额外19来伤；实际死亡触发会转向Rocket，不能收这19点。Rocket的蟹之怒+6力量另算，不能把真实攻击误当仍是38。

纯评分器在此局面：−108.8886→−89.8886，差19；无死亡组合的分数完全相同。该局面是源码支持的公开输入测试，**不是新正常对局、不是通关证据**。八项纯检查通过；Popen禁用，无原生游戏。检查 `python3 reviews/crab-facing-after-kill/test_crab_facing.py`。初始测试用了错误的ENCOUNTER前缀，没有激活主线KB朝向规则，失败日志保留；已用主线裸遭遇ID重测。没有压掉原有ResourceWarning。

## 验证与限制

新100+开发60已有23次双蟹Boss，18死/5存活；这个合并样本只作复盘，不能当新的独立面板或候选收益。对现有trace扫描未找到同时满足「明确单体杀Crusher→下一帧仅Rocket、同回合」的正常证据（扫描零结果保留），所以尚无该分支的正常实局效果证明。

建议主线只开 crab_facing_after_kill，与原策略新100/dev60同种子配对，并计数规则实际命中；很可能只有少数斩杀组合受影响。完整通关与第二幕通过分别记录，不承诺提高多少个百分点。该函数沿用现有预测伤害判断死亡，无法替代公开模拟器对阻止死亡、后续监听与组合顺序的检查。其他敌人、缺Surrounded或已知复活机制保持旧逻辑。
