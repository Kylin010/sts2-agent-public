## 零、怎么读

- **105 条联动，分 10 条线**：消耗线 21、自伤线 10、格挡线 13、力量多段线 11、易伤线 11、打击线 6、出牌数线 14、能力牌线 4、能量线 5、药水×牌 10；另有 7 个输出核心、150 张牌的单卡分、262 件遗物分、52 瓶药水分。
- **分数尺度**：准备度满分 100。一条联动**凑齐**给 0~10 分：6~7 = 社区胜率能拉开十几个百分点的经典组合；4~5 = 线上的主力组合（终端 + 它的引擎）；2~3 = 有用的小联动；1 = 锦上添花。**差一张**给的分一般是凑齐的 30~50%，表示「再拿一张就成型」。单卡分 0~5、遗物 0~5、药水 0~3 是不靠联动的单件强度。
- **怎么算凑齐**：加粗的牌必须都有；「下面至少 N 张」按张数数（同名两张算两张），列在里面的遗物 / 药水持有一件算一张；标「遗物」「药水」的是必须先有的那件。
- **怎么算差一张**：只差一张牌，而且关键件（加粗的牌，或者起头的遗物 / 药水）已经在手。只有燃料没有引擎 / 终端时不算（有力量来源但没有焚烧，不算「焚烧 + 力量」差一张）；差的是遗物 / 药水也不算。
- **⚠ 反联动**：有表里写的牌或遗物时，这条的分数打折（例：钨合金棍把 1 点自伤全部变 0）。
- **社区数据**一栏：进第二幕 Boss 时牌组 + 遗物凑齐这条的局数、最终通关率 vs 没凑齐的通关率（括号里是差，百分点），以及凑齐的局在赢家 / 输家里各占多少。药水联动看不到「手上有没有这瓶」，改成「用了这瓶药水的那场精英 / Boss 战，比同一遭遇的平均多掉几滴血」（负数 = 少掉），按牌组凑没凑齐分两组。**这些都是关联不是因果**：稀有牌多来自精英和 Boss，好牌各自就好、凑在一起胜率是相加的（规律 8），所以分数先按机制定，数据只用来往上 / 往下调。

### 最强的联动（凑齐分 ≥5）

- **无惧疼痛 + 主动消耗手段**（消耗线，7 分）：每烧一张 3 格挡（升级 4），不吃敏捷也不怕脆弱；敌人塞的状态牌、进阶之灾都是免费燃料。燃料多一张 +1，最多 +2。数据 +17（793 局），全表最稳的正信号之一
- **腐化 + 无惧疼痛 / 黑暗之拥**（消耗线，7 分）：技能全 0 费、打出即烧，每张都给格挡和抽牌。腐化只能从先古拿（达夫的尘封魔典必给腐化+），不能当构筑前提
- **壁垒 + 全身撞击**（格挡线，7 分）：攒几回合格挡一下打出去；全身撞击按普通攻击算，吃力量、易伤。升级：壁垒 3→2 费、全身撞击 1→0 费都是质变
- **势不可当 + 无惧疼痛 + 消耗**（格挡线，7 分）：每烧一张 = 3 格挡 + 随机 6 伤（升级 8），不吃力量易伤；只剩一个敌人时等于定向伤害。数据 +21（69 局）；规律 8：势不可当单独 38% → 配无惧疼痛 63%
- **黑暗之拥 + 主动消耗手段**（消耗线，5 分）：每烧一张抽 1：烧牌不再亏手牌。升级降到 1 费是质变
- **幽灵种子 + 消耗收益**（消耗线，5 分）：基础打击、防御变虚无：没打的回合末自动消耗 = 免费燃料 + 战斗内瘦身。数据 +19（44 局，样本小）
- **烘焙手套 + 消耗收益**（消耗线，5 分）：每回合抽完牌自选烧 1 张 +1 永久力量：自带消耗引擎 + 力量成长，状态、诅咒、打击都能烧。数据 +18（212 局）
- **恶魔之舌 + 大自伤牌**（自伤线，5 分）：自己回合第一次掉血原样回来：把最大的自伤放第一个，祭品 = 免费 2 能量 + 抽 3。数据 +13（89 局）

## 十五、怎么合成一个分数（建议）

程序的准备度（`docs/路线分数制.md`）里「联动」这一项封顶 20（`params.json` 的 `combo_cap`）。建议这样合成（参考实现：`check_combos.py` 的 `score_deck`）：

| 分项 | 怎么算 | 上限 |
|---|---|---|
| 联动 | 同一条线的条目相加后先按线封顶（消耗线 20、自伤线 14、格挡线 14、力量多段线 10、易伤线 8、打击线 6、出牌数线 5、能力牌线 4、能量线 5、药水×牌 6），各线再相加 | 30 |
| 核心 | 成型的核心里最高的一个满分 + 第二个的一半 + 「消耗引擎 + 格挡转伤害」同时成型再加 3 | 14 |
| 强力牌 | 牌组里单卡分最高的 8 张（升级的加升级分）相加 × 0.25 | 8 |
| 遗物 | 持有遗物的分相加 × 0.5 | 6 |
| 药水 | 持有药水的分相加 × 1.0 | 4 |
| **合计** | 五项相加 × 0.5 | **20** |

条目分数是「满分 100」的尺度，而程序给联动这一项只留了 20，所以五项相加后再 × 0.5。试算（`check_combos.py --deck …`）：初始牌组 0；第一幕拿到无惧疼痛 + 燃烧契约 + 坚毅约 13（消耗引擎核心已经成型）；第二幕消耗 + 格挡双核心成型、带船夹板和卡戎之灰封顶 20；只有狱火 + 放血约 2.5。

- 一条线内的条目是有意重叠的（无惧疼痛 + 燃料、黑暗之拥 + 燃料、两者同时有……），所以要按线封顶，避免同一套牌在一条线上叠爆。
- 对手是多敌（精英、Boss 有 2 个以上敌人或会召唤）而联动标「单体」，或者对手是单体而联动标「多敌」时，那条 × 0.5。
- **选牌**：一张牌的联动价值 = 拿它之后的合计 − 现在的合计。「差一张 → 凑齐」的增量会自然算出来，不用另写规则。
- 「提供」一栏可以直接用来补准备度的缺口：下一个精英是多怪就看凑齐了几条「群伤」，Boss 长战看「成长」，大招回合看「格挡」。

### 给程序的注意（`policy/combos.py`）

约定的字段（need_all / need_any / min_any / relics_any / potions_any / gives / vs / points / partial / source）之外，这份表还用到：

| 字段 | 意思 | 不处理会怎样 |
|---|---|---|
| `req_relics` / `req_potions` | 必须持有其中至少一件遗物 / 一瓶药水（这条联动靠它起头，例：卡戎之灰 + 消耗） | **会在没有遗物时被误判为凑齐**（只看了燃料够不够） |
| `need_one` | 这些牌里至少有一张（例：无惧疼痛 / 黑暗之拥任一 + 自带消耗的牌） | 少算一个条件，误判为凑齐 |
| `need_any` 按张数 | 同名多张都算（两张燃烧契约 = 两个消耗手段） | 按种类数会少算 |
| `min_any = 0` | need_any 只是加分项，不是条件（例：彼岸咆哮 + 破灭，有头槌再 +1） | 当成 1 会多出一个条件 |
| `per_extra` / `max_extra` | 燃料超过 min_any 每多一张加几分、最多加几次 | 只是少加分 |
| `anti` | 有这些牌 / 遗物时得分 × mult（钨合金棍 × 自伤线、小提琴 × 黑暗之拥、自动打出 × 连环拳……） | 反联动不扣分 |
| 「差一张」要有关键件 | 加粗的牌至少有一张在牌组里，或者是靠遗物 / 药水起头的条目 | 只有燃料时也给差一张分 |
| 核心 `min_cards` / `count_mode` / `relic_companions` / `requires_cores` | 核心牌是「至少 N 种」不是「全部」；打击核心按张数；「消耗 + 格挡」是两个核心同时成型的额外分 | 按「核心牌全部都要」算的话，消耗引擎要同时有无惧疼痛、黑暗之拥、腐化才成型，几乎永远不成型 |

## 十六、数据口径和局限

- 社区数据：`ironclad-a10-v0.111.0.jsonl.gz`，去掉带 modifiers 和中途放弃的局；牌组按初始牌组 + 进阶之灾，用每个节点的得到 / 删除 / 变化正推；遗物按「拿到的层数 < 检查点所在层」算持有。检查点：进第二幕 Boss 时（c2）和进第二幕第一个节点时（c1）。共 9761 局；第一幕结束 5851 局、最终通关 34.2%；进第二幕 Boss 4469 局、最终通关 44.7%（和规律 8 的 4469 局 / 44.7% 一致）。
- 只看牌 id，不看升级；腐化、先古牌的样本很少（腐化 + 无惧疼痛 / 黑暗之拥只有几十局），这类分数按机制定。
- 「凑齐的局胜率高」里混着幸存者偏差和「打的精英多所以稀有牌多」（规律 2），也混着「好牌各自就好」。所以数据只用来调方向：凑齐比没凑齐高 10 个百分点以上的往上调、比没凑齐还低的往下调，没有按数据直接换算分数。
- 药水联动的「少掉几滴血」：用药水的往往是本来就打得难的那场，绝对值偏高，只能横向比较「凑齐 vs 没凑齐」。
- 单人拿不到的多人牌（午夜、炽焰、恶魔护盾、肉盾、群情激愤，以及无色的击倒、协同配合、双打组合等）一张都没有用；其他角色的专属遗物 / 药水也没有用（校验脚本会检查）。
