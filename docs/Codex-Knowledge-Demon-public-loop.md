# 知识恶魔第三次诅咒后，未来来伤仍被错误地混入“再次诅咒”

结论：`foresight._resolve_first` 对未知条件分支平均两条路径。知识恶魔第三次诅咒选择完成后，源码规定只走拍击→洪流→沉思，但预测仍以一半概率回到0来伤的诅咒。本补丁只用**当前可见诅咒效果**证明已完成第三次选择，默认关闭；不读原生 `_curseOfKnowledgeCounter`，不按真实未来或随机数取分支。

## 确认源码与不确定输入

- `KnowledgeDemon.cs:47` 三次选择分别为瓦解6/心智腐烂1、瓦解7/懒惰3、瓦解8/衰朽1。
- `KnowledgeDemon.cs:127` 状态机：诅咒→拍击→洪流→沉思；沉思后的分支在计数<3回诅咒，计数≥3回拍击。
- `KnowledgeDemon.cs:166` 选择完成后递增计数；是否成功获得负面效果不是计数条件。
- `ArtifactPower.cs:19` 可见Debuff收到时改为0并消耗人工制品。因此不能数当前负面徽章并声称精确知道已选择次数。
- 原型中的四个效果，源码搜索只找到上述四张IChoosable卡的Apply；它们均不是普通可生成/可打出的战斗牌。限定原版单人A10知识恶魔，其他版本/模组或来源需另行核对。

`possible_curse_stages` 枚举每槽二选一效果或被挡掉的情况，求与当前可见四个计数一致的已完成阶段集合。空徽章可对应0/1/2/3次，瓦解13可对应2/3次，都保留未知；瓦解8/14/15/21或衰朽1则证明第三槽已完成。矛盾组合、重复计数、缺字段、非整数/异常值返回None，不把缺信息当0。

只在结果恰好(3,)时替换该条件分支为100%拍击。保留旧逻辑给其他遭遇和不确定状态。这个补丁不能解决第三次效果被挡掉且没有可见证据的情况；以后可加“已完成选择”的公开历史，但绝不能读私有计数来补齐。

## 接口和训练一致性

默认 `foresight_public_kd_loop=false`。打开后：

- combatvalue.situation_from_state、combat的EMA预估及mentalmodel.schedule都传入当前公开player_powers，未来伤害和回血使用同一条件解析。
- tools/replay_situations.py可用 `--public-kd-loop` 重提取；只把当时已发生的玩家能力事件复制进快照，close_pending不取之后的力量/能力替代当时输入。训练和运行时的FUT循环含义一致。
- 默认关闭时训练数据结构不新增字段，旧三参数future/schedule调用仍可用。

重提取命令供Claude/value使用（输出放自己的新目录、不能覆盖旧数据）：

```
python3 tools/replay_situations.py --public-kd-loop --out <新目录>/human-turns-kd.jsonl --runrec-cache <新目录>/runrec.json
```

本窗口没有运行全量重提取或训练，也未更改同伴数据/模型。开关改变FUT输入，但现有价值网络在旧FUT上训练，分布偏移仍需主线评估；训练一致性接口不等于模型已经重训。
