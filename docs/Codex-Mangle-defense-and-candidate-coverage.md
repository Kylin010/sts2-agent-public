# Mangle 的减力量遗漏会排除正确的防御候选

结论：当前主线 `combat._score` 把 Mangle 作为伤害牌计算，没有扣除它对敌人每段攻击的临时减力量收益。`search.py:444` 从这个规划器取前 K 名候选，因此遗漏不只影响无推演打法，也可能让公开推演没有机会比较正确方案。建议首先测试默认关闭的 `public_mangle_strength_score`；本报告没有声称通关率提高。

## 源码证据

- `Models.Cards/Mangle.cs:34` 攻击后应用 ManglePower；升级前减10力量，升级后减15，牌费3。
- `Models.Powers/ManglePower.cs` 继承 TemporaryStrengthPower，IsPositive=false。
- `Models.Powers/TemporaryStrengthPower.cs:164` 应用时施加负力量；`AfterSideTurnEnd` 在拥有者完成其回合后移除并返还。因此防的是当前敌方回合，不能当作永久减伤。
- `Models.Powers/StrengthPower.cs:16` 对拥有者的每一段 powered attack 加力量；多段攻击必须逐段扣减并将伤害截断到0。
- `MonsterMoves.Intents/AttackIntent.cs:GetSingleDamage` 显示经过伤害修正的整数；Weak/Vulnerable 存在时，不能直接从显示伤害减10/15。
- 基线 `policy/combat.py:262` 只从当前意图取来伤，后续仅处理部分虚弱/巨像等效果，未处理 strengthloss。

已完成独立模型 PUB6447 的公开第三形态局面：英雄65血、3能量，敌人313血、无形1，意图11×3；手有升级Mangle减15力量以及三张防御。这是独立预测局面，**不是实际正常游戏或真实未来信息**。

## 改动与边界

`policy/public_strength_loss.py:mangle_incoming_bound` 用显示的每段伤害、段数、可见strengthloss和已审Weak/Vulnerable比例，返回减力量后伤害的保守上界。由于显示值向下取整，使用区间而不是伪造准确底层数值。未知直接伤害修正、未知遗物、组合同时加敌人力量、激怒与技能组合、人工制品按ID或名字识别、缺失显示值等返回None，不把未知当0。

只在开关True且函数支持时替换当前来伤估计；默认False，原生模拟器和真实状态不变。15项纯检查覆盖多段归零、虚弱取整区间、易伤、目标归属、未知机制拒绝、私有字段不变性；最新master公开示例使用Popen禁用校验，关闭开关后结果与基线完全相同，无新原生对局。复现：`python3 reviews/mangle-visible-defense/reproduce_planner.py`；检查：`python3 reviews/mangle-visible-defense/test_mangle_strength.py`。

本函数是有明确范围的保守评分修正，不是完整未来监听器证明。已知还有组合顺序/额外触发和特殊方向问题需要审查。

按现有新100/dev60同种子整局面板，候选只开public_mangle_strength_score；完整保留TECH与所有死亡。主指标第二幕通过率、实际双Boss通关另列，同时记录Mangle在候选榜的覆盖率、进入公开推演的比例、知识恶魔过载与沙虫双击时实际选用次数及掉血。不要只统计已经拿到Mangle并存活的局来宣称收益。尚无可诚实承诺的提升百分点。

## 战斗价值网络的相关缺口

`combatvalue.features` 与 `data/combat_value_human.json` 包含enc、round、敌总力量、来伤、weak/vuln，但没有临时力量损失的到期字段、逐敌招式位置、剩余沙坑期限或复活形态预算。`train_combat_value_human.py:44` 的目标是future掉血减去当前unblocked，再加死亡惩罚；这不是通关概率。正确加入当前减伤仍不能保证网络知道下一回合力量返还，或知道沙坑会无视HP强制死亡。下一题应分别审查这些遗漏并给特征方案，不重复已经阴性的单纯增加推演量。
