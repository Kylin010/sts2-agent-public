# 战斗价值网络：用人类对局训练（10/4，分支 claude/human-value-net）



## 复现

```bash
python3 tools/replay_situations.py            # 929 个社区回放 → results/human-turns.jsonl（约 20 秒），打印各字段核对结果
python3 tools/train_combat_value_human.py     # → data/combat_value_human.json（约 1 分钟），打印和三个对照的比较
```

## 程序里切换

- 单次：`python3 run.py ... --set cv_file=combat_value_human.json`
- 默认：params.json 的 `"cv_file"` 改成 `"combat_value_human.json"`
- 格式和 combat_value.json 一样，policy/combatvalue.py 不用改。隐藏层 64（4 个 16 的网络取平均合成一个），predict 约 120 微秒 / 次（旧模型 77）。
- 去掉了 `ehp` / `ehp_all` 两个不封顶的特征：瀑布巨兽无限血阶段运行时血量是 999999999，ReLU 外推会算出几百万。敌人血量的信息由封顶的 turns_left / inc_x_turns / fut_x_turns 带。

## 数据

- 回放：符合条件（v0.111.0（含同一提交的 "0.1.0"）/ v0.107.1、单人、标准、无修改器、无影响玩法的模组）662 局 → 打完的 8642 场战斗（有回合结束局面的 8540 场）、34759 个局面（第一幕 53%、第二幕 27%、第三幕 20%）。
- 读档 / 重开：放弃的那一遍没有结果，丢掉 1660 遍；911 场战斗重来过（留最后打完的那遍）。只用「整局一次都没重来过」的对局训练，检验误差几乎一样（13.44 vs 13.47），默认全用。

## 字段还原（核对结果）

| 字段 | 方法 | 核对 |
|---|---|---|
| 我方血量 | hp 事件 | 进场血量 = 整局记录上一层 94% |
| 血量上限 | 整局记录同种子这一层之前 | 85% 的战斗有，其余用开局 + max_hp 事件 |
| 格挡 | block 累加、挨打扣、敌方回合后清零 | v6+ 的 left 字段 100% 一致 |
| 力量 / 敏捷 / 减益 / 能力数 | power 事件增量 | — |
| 敌人意图 | 下一个敌方回合它实际打到我的伤害（v7 用显示值） | v7 显示值 = 实际 96% |
| fut | 实际出的招 + foresight 出招表 | 96% 认得出招 |
| 敌人血量 | 开场血 − 命中，回血招 / 复活 / 召唤特判 | 打死时记账血量 = 最后一下 83%（同名敌人分不清、召唤物血量随机） |
| 牌组张数 | 开局 + 获得 − 删除，存档退出时以整副牌为准 | 86% 一致，第一次洗牌再修正 |
| 抽牌堆张数 | 逐张记账，洗牌时应为 0，不为 0 就倒推修正这一段 | 洗牌前为 0：78%；v7 洗牌后张数 93% |

局面取在 end_turn 事件那一刻（回合结束触发已发生，比如覆甲格挡、灼伤扣血）；我们自己的数据取在按「结束回合」之前，差几点格挡 / 血。

## 结果（按对局划分，检验 124 局 7066 个局面；目标 = 之后掉的血 − 这次敌方回合漏伤 + 死亡 30）

| 模型 | 人类检验 RMSE | 相关 | 我们的局面（旧模型的检验场次）RMSE / 相关 / 偏差 |
|---|---|---|---|
| 只猜平均 | 16.15 | — | 31.7 / — / −15.1 |
| 线性回归 | 13.73 | 0.53 | 25.0 / 0.67 / −11.0 |
| 现有 combat_value.json（我们的对局） | 34.82（偏高 19.5） | 0.36 | 15.4 / 0.83 / +0.5（在自己的数据上） |
| **人类模型** | **13.57** | **0.55** | 27.2 / 0.68 / −14.9 |

- 第三幕：人类模型 15.2，现有模型 62.3（我们的数据几乎全是第一幕）。
- 我们的局面上人类模型系统性低估约 15 血：同样的局面我们掉血多得多（人类会打）。所以 cv_weight / search_future_weight 可能要重调；规划器比较的是同一回合不同打法的高低，排序更重要：同一场战斗里两个局面谁之后掉血更多，人类检验集排对 94.7%（现有模型 90.4%），我们的局面 88.6%（现有模型 89.9%，那是它自己的数据）。
- 灵敏度（改一处看预测往哪变，3000 个局面）：主怪血 −10 → 95% 预测降低（现有模型 83%）；我方力量 +2 → 96% 降低（现有 62%）；给敌人挂易伤，现有模型反而预测更多掉血（数据里易伤多在难打的仗），人类模型 −0.65。

## 数据量

- 学习曲线：训练对局 54 / 108 / 217 / 434 局 → 检验 RMSE 14.2 / 13.9 / 13.65 / 13.57，已经接近平。同样特征下再加同类回放收益小；剩下的误差主要是抽牌 / 敌人随机，要再往下得加特征（手牌、牌组构成、遗物、药水）——那时才需要更多数据。
- 更多逐回合数据：spire-codex 的 `/api/replays` 还有别的进阶和别的角色的录像（tools/fetch_replays.py 参数换角色 / 进阶即可下载，没下）；敌人一侧完全一样，玩家一侧的特征（牌组每回合伤害）对别的角色也能算。research/community-ironclad-20261002 的 80 局和这 929 局重复 79 局。
- 整局记录（ironclad-a10-all.jsonl.gz）：7 万局里 v0.107.1 / v0.111.0 标准单人 3.1 万局、33 万场战斗（回放的 38 倍），只有每层掉血、没有逐回合。
  用进场时的信息（遭遇、幕、层、血、上限、牌组张数 / 升级 / 每回合伤害）预测这场总掉血，同一批检验战斗上 RMSE 15.07（相关 0.61），
  逐回合人类模型在第 1 回合结束时 14.89（相关 0.62）——几乎一样；两者平均 14.41。
  能做：每场战斗的掉血先验（路线 / 精英判断、选牌时「这张牌让各遭遇少掉多少血」）、给逐回合模型做遭遇级校准。
  做不到：同一回合里挡还是打、先后顺序这种取舍——那必须要逐回合数据。
